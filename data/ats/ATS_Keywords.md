# AI Engineer

## ATS Overview

When screening for an AI Engineer, recruiters and Applicant Tracking Systems (ATS) actively search for candidates who bridge software engineering with modern generative AI capabilities. The ATS is configured to filter out candidates who only possess traditional data science skills (like pandas or regression) and instead looks for specific API integrations (OpenAI, Anthropic), orchestration frameworks (LangChain, LangGraph), and backend deployment skills (FastAPI, Docker). Recruiters search for evidence of applied AI: building autonomous agents, reducing API latency, implementing vector search, and preventing hallucinations in production environments.

## Resume Section Recommendations

Skills: Group skills logically (e.g., "AI & LLMs:", "Backend & Cloud:", "Vector Databases:"). Do not mix standard libraries (pandas) with orchestration frameworks (LangChain).

Projects: Focus entirely on applied AI integrations. Detail the exact models used (e.g., `gpt-4-turbo`, `claude-3-opus`) and the vector database utilized.

Experience: Emphasize business impact. Mention token cost reductions, latency improvements, and user adoption metrics of AI features.

Education: List degree. If lacking a CS degree, heavily emphasize AI-specific bootcamps or DeepLearning.AI certifications.

Certifications: AWS Machine Learning Specialty, DeepLearning.AI Generative AI.

Publications: Less critical for an AI Engineer compared to a Research Scientist. Include only if highly relevant (e.g., a blog post on optimizing RAG chunking).

Achievements: Hackathon wins specifically related to Generative AI or LLMs.

---

## Common ATS Mistakes

- Keyword stuffing: Listing "LangChain, LangChain, LangChain" invisibly in white text (ATS systems flag this as spam).
- Poor formatting: Using complex multi-column layouts that parse incorrectly, misaligning the AI Engineer title.
- Images: Including graphs or profile pictures that confuse the OCR/ATS parser.
- Tables: Using tables to list tech stacks instead of standard bulleted lists.
- Missing skills: Failing to mention standard backend skills (FastAPI, Docker) while applying for an AI Engineer role.
- Missing measurable achievements: Stating "Built a chatbot" instead of "Built a RAG chatbot serving 5,000 MAU, reducing support tickets by 20%."
- Weak project descriptions: Failing to specify which LLM API was used and how hallucinations were mitigated.

# Machine Learning Engineer

## ATS Overview

When screening for a Machine Learning Engineer, the ATS heavily indexes on mathematics, algorithmic modeling, and strict MLOps deployment tools. While an AI Engineer is screened for API integration, the Machine Learning Engineer is screened for model training, optimization, and scalable inference. Recruiters search for evidence that the candidate can handle messy tabular or unstructured data, train robust predictive models (using Scikit-Learn or PyTorch), and deploy them via Kubernetes or AWS SageMaker while monitoring for data drift.

## Resume Section Recommendations

Skills: Strictly separate Modeling skills (PyTorch, XGBoost) from Deployment/MLOps skills (Docker, MLflow, Kubernetes).

Projects: Avoid standard academic datasets (Titanic, MNIST). Detail projects that process custom data, track experiments, and serve predictions via API.

Experience: Focus heavily on optimization metrics. State inference times (e.g., "<50ms latency") and data scale (e.g., "trained on 500GB of log data").

Education: High priority on MS or Ph.D. in quantitative fields (Computer Science, Statistics, Mathematics).

Certifications: AWS Machine Learning Specialty, Certified Kubernetes Administrator (CKA).

Publications: Highly valuable if published in top-tier conferences (NeurIPS, CVPR, ICML).

Achievements: Top 10% finishes in Kaggle competitions, open-source contributions to PyTorch or Scikit-Learn.

---

## Common ATS Mistakes

- Keyword stuffing: Repeating "Machine Learning" 20 times instead of listing specific algorithms (Random Forest, SVM).
- Poor formatting: Using complex graphics that prevent the ATS from parsing the "Machine Learning Engineer" job title.
- Images: Using charts to show model accuracy on the resume.
- Tables: Using tables to format the skills section.
- Missing skills: Listing PyTorch but failing to list Python or SQL.
- Missing measurable achievements: Stating "Trained a model to detect fraud" instead of "Engineered an XGBoost fraud detection model that reduced false positives by 18%, saving $1.2M annually."
- Weak project descriptions: Mentioning Jupyter Notebooks without mentioning how the model was deployed.
